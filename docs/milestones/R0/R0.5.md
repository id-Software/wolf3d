## Purpose and scope

R0.5 establishes a sanitizer and performance baseline for the current synthetic
test scope. It covers AddressSanitizer/UndefinedBehaviorSanitizer execution of
representative synthetic C harnesses, lifecycle/restart, allocation/cleanup,
resource error paths, Classic rendering, Enhanced rendering, and reproducible
synthetic performance measurements. It does not introduce new gameplay behavior,
rendering changes, dependencies, or commercial asset requirements.

## A14 — ASan/UBSan execution

### Method

Representative synthetic Python unittest suites were executed with `SANITIZE=1`.
The test harnesses add `-fsanitize=address,undefined -fno-omit-frame-pointer`
to GCC compile flags when `SANITIZE=1` is set (verified in the existing test
wrappers, e.g. `tests/test_engine.py`, `tests/test_render.py`,
`tests/test_display.py`, `tests/test_presentation.py`, `tests/test_classic.py`).

Commands were run from the repository root. Each command was bounded by an
external `timeout` and its stdout/stderr was captured to a log file; the exit
code was appended to the log.

| --- | --- | --- |
| `test_engine.py` | Yes — compiled engine/ui/game/combat/campaign/boss/finale harnesses with SANITIZE flags | **Yes** — some tests invoke prebuilt `WOLF3D_BINARY` (`--check-ui`, `--check-level`, `--menu --frames`, malformed-data app runs) |

| `test_render.py`, `test_classic.py`, `test_display.py`, `test_presentation.py`, `test_save.py`, `test_controls.py`, `test_loading.py`, `test_audio.py`, `test_dos_menus.py`, `test_dos_ui_reference.py`, `test_demo_sync.py` | Yes — compiled test harness binaries with SANITIZE flags | No WOLF3D_BINARY invocation identified in these wrappers |

## A16 — Performance baseline

### Method

A synthetic performance benchmark harness, `tests/synthetic_perf_benchmark.c`,
was added. It uses only synthetic game fixtures (`game_files()` from
`tests/game_fixtures.py`), requires no owned WL6 data, and reports CSV output.

Two binaries are compiled:

- CPU-only: GCC 14.2.0, `-std=c11 -O2 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror -g`, linked with SDL3 static lib for timing.
- SDL-profile: same flags plus `-DWOLF3D_BENCHMARK` to enable existing WL_PROFILE instrumentation and separate convert/upload/present phases.

### Reproducible workflow

Executable workflow (preferred):

```sh
python3 tools/r0_5_synthetic_perf.py --timeout 600
```

This script checks prerequisites, generates synthetic fixtures via
`tests/game_fixtures.py`, compiles both binaries, runs CPU and SDL(dummy/software)
benchmarks, and writes logs/CSV/summary under ignored `build/validation/R0.5/`.
Raw outputs: `build/validation/R0.5/logs/perf-cpu.stdout.log`,
`build/validation/R0.5/logs/perf-sdl.stdout.log`,
`build/validation/R0.5/logs/perf-cpu.csv`,
`build/validation/R0.5/logs/perf-sdl.csv`,
`build/validation/R0.5/perf-summary.txt`.

```sh

  ./build/validation/R0.5/synthetic_perf_bench_sdl \
  build/validation/R0.5/perf-data build/validation/R0.5/perf-user-sdl --sdl
```

Exit: 0. Raw log: `build/validation/R0.5/logs/perf-sdl.stdout.log`.

Fixed render dimensions are explicitly selected per case:
`high_resolution=true`, `render_auto=false`, `render_width=w`,
`render_height=h`. After `VL_DisplaySet()`, the benchmark reads back

- `frame_total`: wall-clock time around `GameDrawPaused()` + `VW_UpdateScreen()` (game draw plus SDL update path).

## Findings and limitations

- No application-owned ASan/UBSan findings were observed in the executed synthetic
  sanitizer matrix.
- Sanitizer coverage is bounded to the selected suites and synthetic fixtures; it
  is not a proof of absence of bugs in all paths.
- 21 full-regression tests remain skipped due to owned Wolfenstein data or
  environment-dependent requirements; they were not converted to passes.
- Performance numbers are from one Linux x86-64 machine with SDL dummy/software
  for the SDL presentation phase. They are baselines, not portable performance
  claims. Variance spikes are visible in raw distributions (e.g. populated
  1920x1080 CPU p99/max, 1280x720 SDL present) and are reported, not smoothed.
- Allocation measurement is limited to observable `ru_maxrss` and end-of-run
  `MM_TotalBytes()`; it is not a full allocator trace.
- No hardware-accelerated GPU presentation, physical display, Windows/macOS, or
  owned-data WL6 performance run was executed for this revision.
- `tests/synthetic_perf_benchmark.c` is a new synthetic benchmark harness; it is
  not yet wrapped by a canonical `tools/` command (R0.6 scope).
