# R0.4.1 Graphics baseline inventory

**Revision:** R0.4.1

**Branch:** `docs/revival-roadmap-and-validation`

**Inspected commit:** `043884e`

**Status:** inventory complete; R0.4 acceptance criteria A11-A13 are **NOT RUN**

**Scope:** documentation and source inspection only. No capture tool, renderer,
test, dependency, fixture, asset, or baseline image was added or changed.

## Objective and boundary

Audit the graphics capture and comparison facilities already present for the
Classic 4:3 and Enhanced widescreen paths, then define the smallest reproducible
R0.4 implementation. Existing facilities are labelled **EXISTS** below.
Unimplemented recommendations are labelled **PROPOSED**.

This inventory does not establish an R0.4 baseline, perform human visual
approval, or satisfy A11-A13. It does not implement R0.4.2.

## Rendering and capture paths that exist

### Production paths

| Capability | Status | Source and observed behavior |
|---|---|---|
| Classic indexed source | **EXISTS** | `src/engine/ID_VL.c/.h` owns the 320x200 indexed `framebuffer` and 256-entry VGA palette. `WL_DRAW.c`/`WL_SCALE.c` draw the Classic world, sprites, HUD, and weapon into it. |
| Enhanced indexed target | **EXISTS** | `src/engine/WL_RENDER.c/.h` renders a world snapshot into caller-owned `wl_render_target` storage. `WL_RENDER_TARGET.c/.h` bounds width, height, stride, capacity, and pixel writes. |
| Aspect calculation | **EXISTS** | `src/engine/WL_ASPECT.c/.h` fits explicit ratios. `src/platform/display_settings.h` defines Auto, 4:3, 16:9, 16:10, 21:9, and 32:9 plus Classic/Enhanced, internal render size, integer/fit, filter, smoothing, window, drawable, and fullscreen settings. |
| Immutable scene sampling | **EXISTS** | `src/engine/WL_PRESENT.c/.h` captures and interpolates previous/current camera, actor, door, static, tile, pushwall, weapon, and death state for Enhanced presentation. |
| SDL composition | **EXISTS** | `src/platform/sdl_video.c::VL_DrawScreen` converts indexed pixels through the active palette, uploads the Classic texture or Enhanced texture, applies the logical presentation, and renders it. `VW_UpdateScreen` presents it. |
| Named-path capture | **EXISTS** | `src/platform/sdl_video.c::VL_Capture(path)` redraws, calls `SDL_RenderReadPixels`, and writes BMP through `SDL_SaveBMP`. It captures the composed renderer result, not the raw indexed buffer. |
| User screenshot | **EXISTS** | `VL_Screenshot()` writes collision-resistant `screenshot-<ticks>-<n>.bmp` files beneath SDL's `wolf3d-revive` preference path. F12 invokes it. Names are intentionally time-dependent. |
| CLI single capture | **EXISTS** | `src/main.c` accepts `--capture local.bmp` with a windowed run and restores the prior palette after capture. `--frames N`, `--menu`, `--level`, and `--no-audio` exist, but there are no CLI flags selecting renderer, internal resolution, aspect, filter, or a named deterministic gameplay scene. |

`VL_Capture()` has an important boundary: SDL renderer readback follows the
active logical presentation. `tests/video_tests.c` verifies that after a
1000x600 Classic resize the saved BMP is the 800x600 logical viewport, not the
full drawable with its 100-pixel side bars. Tests that need the complete output
and black bars, such as `tests/display_tests.c::Geometry`, temporarily disable
logical presentation and call `SDL_RenderReadPixels` directly. A baseline must
state whether it represents logical content or the complete drawable; the two
are not interchangeable.

The CLI capture occurs before the main presentation loop. It is useful for
startup/signon diagnostics (`tests/test_signon.py`) but is not presently a
general fixed-tick scene capture interface. Its result can also inherit the
configuration in the SDL preference directory unless the caller isolates
`XDG_DATA_HOME` and supplies known configuration.

## Existing comparison coverage

### Exact checks already available

- **Classic source pixels:** `tests/render_original_tests.c` and
  `tests/render_native_hashes.c` produce exact framebuffer hashes compared by
  `tests/test_render.py` with committed CSV files. These require the expected
  legally owned WL6 revision and skip otherwise.
- **Synthetic Classic SDL output:** `tests/test_signon.py` reads BMP headers,
  normalizes row direction/stride, and checks scaled pixels against the
  generated indexed source and original palette without an imaging library.
- **Enhanced CPU output:** `tests/render_tests.c` performs exact indexed pixel,
  memory-guard, repeated-image hash, HUD, aspect, sprite, opacity, weapon, and
  wall-occlusion assertions.
- **Classic versus wide geometry:** `render_tests.c::Wide` checks that central
  world pixels and HUD content agree exactly while widescreen adds rays rather
  than stretching the Classic scene.
- **SDL software output:** `render_tests.c::AutoScaling` compares a captured
  synthetic 4K nearest-neighbor image pixel-for-pixel with a directly rendered
  1920x1080 indexed target when the dummy backend supplies exact 3840x2160
  output.
- **Window composition:** `display_tests.c::Geometry` disables logical
  clipping, reads the full output, and checks black bars, red/green halves,
  fit/integer geometry, and drawable dimensions.
- **Presentation interpolation:** `presentation_tests.c::Images` hashes direct
  indexed render targets and proves camera/door/pushwall intermediate images
  are distinct and independent from later mutations of the live world.

### What does not yet exist

- No committed synthetic Classic and Enhanced image set representing the same
  named scene, camera, tick, palette, view size, and content identity.
- No baseline manifest or sidecar metadata schema.
- No single command selects scenes, renderer modes, output sizes, aspects, and
  evidence directory with a bounded result summary.
- No generic image comparator reports changed-pixel count, bounding box,
  channel error, masked regions, or an explanatory diff image.
- Existing screenshot tests usually verify file count/signature or exact
  hand-picked pixels; saved BMPs are not broadly compared with goldens.
- `WOLF3D_CAPTURE_DIR`, `M8_CAPTURE`, F12, and CLI `--capture` are separate
  opt-in surfaces with different naming and scene timing.
- Fullscreen checks under the dummy driver test state transitions, not a
  physical monitor, compositor, DPI, HDR, or exclusive-mode result.
- Linear filtering and hardware renderer output are not portable pixel-exact
  oracles. Existing exact output checks deliberately use the SDL software
  renderer and nearest filtering.
- Captures do not embed or accompany commit, fixture, driver, renderer,
  dimensions, aspect, palette, tick, camera, or tolerance metadata.
- The existing owned-data hash oracles cannot be redistributed as commercial
  screenshots and do not provide a synthetic public visual baseline.

## Synthetic assets and scene control

`tests/game_fixtures.py` builds project-generated map, VSWAP, graphics, UI,
sprite, and campaign/finale inputs in temporary directories. `finale_files()`
is already used by all three principal graphics suites. These fixtures require
no commercial data and are removed after each Python test.

The fixture art is diagnostic rather than aesthetic: deterministic palette
indices, simple posts, flat pictures, and bounded maps make exact sampling and
occlusion visible. This is suitable for public regression baselines. Owned WL6
checks remain a separate private compatibility layer and must not produce
committed screenshots.

Current scene construction is distributed across harness functions. The most
reusable existing scene ingredients are:

- `render_tests.c::Visual`: near/far statics, ordering, explicit opacity,
  opaque palette index zero, wall occlusion, and weapon placement;
- `presentation_tests.c::Images`: fixed camera plus closed/opening door and
  moving pushwall interpolation;
- `classic_tests.c::Views` and `Border`: all Classic view sizes and
  near-sprite/wall/HUD clipping;
- `campaign_sdl_tests.c`: before/moving/open pushwall states;
- `render_tests.c::DeathContinuity`: fixed death phases across three render
  sizes and all five explicit aspects plus Auto.

## Proposed resolution and aspect matrix

Internal render size, logical gameplay aspect, and final drawable size are
independent settings and must be recorded separately.

### Automated required matrix

| Renderer | Internal source/target | Gameplay aspect | Drawable/window | Purpose |
|---|---:|---:|---:|---|
| Classic | 320x200 indexed; 320x240 corrected logical canvas | 4:3 | 640x480 | Small exact nearest/software reference. |
| Classic | same | 4:3 | 1280x720 | Centered 4:3 content and side-bar/full-output geometry. |
| Classic | same | 4:3 | 1001x601 | Non-integer fit and edge-rounding reference. |
| Enhanced | 640x480 | 4:3 | 640x480 | Small target and Classic-comparable framing. |
| Enhanced | 1280x720 | 16:9 | 1280x720 | Primary widescreen reference. |
| Enhanced | 1280x720 | 16:10 | 960x600 or 1280x800 | Explicit aspect fit and HUD centering. |
| Enhanced | 1280x720 | 21:9 | 1680x720 | Ultrawide ray extension and clipping. |
| Enhanced | 1280x720 | 32:9 | 2560x720 | Maximum supported aspect boundary. |
| Enhanced Auto | resolved target recorded | Auto | 1001x601 | Real output-derived aspect and non-integer dimensions. |

The existing 1920x1080 fixed target and Auto-derived 1920x1080, 1920x803,
and 1920x540 targets should remain assertion coverage. A 1920x1080 capture can
be included for the primary scene, but duplicating every scene at every
resolution is not necessary for the first baseline.

### Manual/platform matrix

- Native Linux software renderer at the primary Classic and Enhanced modes.
- Native Linux default accelerated renderer at the same modes, visually
  inspected but not assumed pixel-identical to software.
- Fullscreen enter/exit and restored window size on a physical display.
- Windows/Wine capture only when the R0.4 contract selects it; Wine/dummy is
  not evidence of physical Windows display behavior.
- High-DPI or non-1x drawable scaling is **NOT RUN** unless such hardware or a
  verified backend is available.

## Proposed capture metadata

Every baseline/candidate pair should have a machine-readable record containing:

- schema version, scene ID, baseline role, repository commit, dirty-tree flag,
  exact command, exit code, and capture timestamp;
- fixture generator and content identity/hash; explicit statement that inputs
  are synthetic or private (private captures never committed);
- Classic/Enhanced mode, view size, authoritative tick and RNG index, camera
  position/angle, relevant door/pushwall/actor/static state, weapon/frame, and
  palette identity;
- internal indexed width/height/stride, requested aspect and resolved aspect,
  fitted scene/UI rectangles, logical presentation size, window point size,
  drawable pixel size, and pixel density when available;
- fullscreen/windowed, integer/fit, Auto/fixed resolution, nearest/linear,
  smooth interpolation, VSync, and presentation sample time;
- OS/architecture, compiler, SDL version, SDL video driver, render driver or
  renderer name, pixel format, and capture method (`indexed-target`,
  `logical-VL_Capture`, or `full-output-readback`);
- image width/height/format, normalized pixel hash, baseline hash, comparison
  policy/version, changed-pixel metrics, and evidence paths;
- manual reviewer, date, result, and notes where visual approval is required.

The metadata must be written beside ignored run evidence even when the baseline
image itself is later approved for source control. A BMP filename alone is not
reproducibility evidence.

## Proposed comparison policy

1. **Exact indexed comparisons:** Classic 320x200 framebuffer and Enhanced
   CPU `wl_render_target` output from synthetic fixtures must compare every
   indexed pixel exactly. Store/hash canonical row-major pixels, not structure
   padding or pointers.
2. **Exact canonical SDL profile:** SDL software renderer, nearest filtering,
   fixed palette, fixed drawable, and fixed logical rectangle may compare
   normalized RGBA pixels exactly. Normalize BMP row direction, padding, and
   header fields before hashing. `tests/test_signon.py` already demonstrates a
   dependency-free BMP reader.
3. **Full-output geometry:** use direct full renderer readback, not
   `VL_Capture`, when black bars and drawable edges are part of the assertion.
   Record the logical rectangle and compare bars separately from content.
4. **Linear/accelerated/platform output:** do not apply an unexplained global
   tolerance. First compare deterministic geometry and the indexed source.
   If R0.4.2 finds real backend variance, define a named profile with measured
   per-channel maximum, changed-pixel budget, excluded edge mask, and a diff
   image. Keep human visual review mandatory.
5. **Interpolation and animation:** freeze the authoritative tick and exact
   sample timestamp/alpha. Otherwise a legitimate sub-tick difference is not a
   renderer regression.
6. **Palette conversion:** synthetic nearest/software output should retain the
   existing exact VGA expansion `(value << 2) | (value >> 4)`. Do not hide
   palette changes behind perceptual tolerance.

No tolerance value is asserted by this inventory because no candidate/baseline
variance set was measured in R0.4.1.

## Smallest practical R0.4.2 implementation

1. Extend `tests/render_tests.c` and its existing Python driver rather than add
   a new renderer or scene model. Give the existing synthetic `Visual`, door,
   and pushwall setups stable scene IDs and an opt-in evidence directory.
2. Emit canonical indexed pixels for Classic and Enhanced at the same frozen
   state. Add final SDL captures only for the small output matrix where
   composition itself is under test.
3. Reuse `VL_Capture` for logical-content BMPs and the already proven direct
   full-output readback pattern from `display_tests.c` for bars/drawable
   geometry. Do not change production capture behavior merely for tests.
4. Have the existing Python unittest write/read a small versioned manifest,
   normalize pixels, compare exact profiles, and report dimensions, changed
   pixel count, bounding box, and hashes. Use only the Python standard library
   or existing SDL C path; add no imaging dependency.
5. Keep approved redistributable synthetic goldens small. Store ordinary run
   captures, diffs, logs, and private owned-data images under ignored
   `build/validation/R0.4/`.
6. Run the focused graphics suites, complete regression, and manual visual
   checklist before assigning PASS to A11-A13. Wrapper/CI orchestration remains
   R0.6 work.

This sequence adds evidence plumbing around facilities that already exist. It
does not require renderer refactoring, a new capture executable, or a general
image-processing framework.
