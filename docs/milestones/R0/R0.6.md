## Purpose and scope

R0.6 implements a lightweight validation orchestrator over existing Python
unittest suites and scripts. It provides milestone selection, bounded execution,
clear progress/status reporting, per-job logs, and machine-readable JSON
summaries. It does not change gameplay, renderer, save formats, or add
dependencies.

## Architecture

- `tools/validation/run.py` — Python stdlib orchestrator. Defines explicit job
  registry, selects jobs by milestone/category, runs each job in a new process
  group, captures stdout/stderr to a log file, enforces per-job timeout with
  process-group termination, writes `summary.json`.
- `tools/test.sh` — thin bash wrapper delegating to `run.py`.
- `tests/test_validation_runner.py` — orchestration unit tests (synthetic helper
  commands; no full engine compile).

Design choices:
- Reuse existing unittest suites and `tools/r0_5_synthetic_perf.py`; no test
  framework rewrite.
- No third-party Python dependencies.
- Bounded allowlist for environment metadata in JSON (platform, python, cwd, cc).
- `WOLF3D_UPDATE_BASELINES` is removed from job environments to prevent
  accidental baseline regeneration.

python3 tools/validation/run.py R0.6 --list

python3 tools/validation/run.py R0.6 --job r06-runner-tests

tools/test.sh                    # default R0.6
tools/test.sh --graphics         # R0.4 graphics category
tools/test.sh --sanitizer        # R0.5 sanitizer category
tools/test.sh --performance      # R0.5 performance category
tools/test.sh --all              # all milestones/jobs

## Progress, timeout, and failure behavior

Each job prints `START [milestone] id: description` with timeout and command.
Jobs run in a new process group (`start_new_session=True`); on timeout the runner
sends SIGTERM to the process group, waits briefly, then SIGKILL, preventing
orphan child processes. Each job ends with `PASS|FAIL|TIMEOUT|SKIP|NOT RUN`,
exit code, and duration. Missing mandatory prerequisites are reported as
`NOT RUN` and fail the overall run. A compile is never reported as a test pass;
the runner reports the test command's exit status.

## JSON summary schema

`build/validation/<milestone>/<run-id>/summary.json` (schema_version 1):

- `milestone`, `started_at`, `ended_at`, `duration_s`, `overall_status`
- `environment`: bounded allowlist (`platform`, `python`, `cwd`, `cc`)
- `jobs[]`: `id`, `milestone`, `description`, `command`, `category`, `mandatory`,
  `timeout`, `status`, `exit_code`, `duration_s`, `started_at`, `ended_at`,
  `log_file`, `message`

Per-job logs are written as `<job-id>.log` in the same run directory.

## CI configuration

`.github/workflows/validation.yml` runs on push/PR to
`docs/revival-roadmap-and-validation`. It executes `python3 tools/validation/run.py R0.6`
(mandatory synthetic CPU+graphics+runner tests) on `ubuntu-latest` with
SDL3 built/cached, dummy video/software render/dummy audio. Validation logs are
uploaded as artifacts on failure.

Not run in CI by default: sanitizer and performance jobs (separately selectable),
owned-data WL6 tests, GPU/physical-display checks. CI passing is **not claimed**
until a real workflow run confirms it.

## Known limitations

- Sanitizer jobs are instrumented-harness coverage as documented in R0.5; app
  subprocesses through prebuilt `WOLF3D_BINARY` are not ASan-instrumented.
- Owned WL6 data tests remain environment-dependent skips; not claimed as passes.
- CI workflow is unconfirmed by a real GitHub Actions run in this session.
- Performance jobs are evidence-only; no FPS target gate.
- `all` includes sanitizer/perf and can be expensive; CI default uses R0.6.
