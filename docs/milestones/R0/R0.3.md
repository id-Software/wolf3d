## Deterministic headless testing implemented

`tests/test_engine.py` compiles the engine core with the filesystem adapters
only; the synthetic `test_game_synthetic` path runs `game-tests` against
archives generated by `tests/game_fixtures.py`. No SDL window is created. The
C tests use the `CHECK` macro in `tests/game_tests.c`, which reports source
line, expression and `CA_Error()` on failure, giving actionable diagnostics
without a renderer.

The fixture map is fixed: player spawn at tile `(2,2)`, one closed door at
`(6,2)`, perimeter walls, and no actors or statics at startup. All new tests
are gated by `argc == 2`, so they run only in synthetic fixture mode and never
in the commercial WL6 mode.

## Coverage by area

### Map boundary and collision

`TestMapBounds()` resets actor/collision grids with `InitObjects()` and clears
`tilemap` to make a fully open 64x64 traversable region. It checks `TryMove()`
at both `MINDIST` edges on x and y, verifies that the opposite side is
rejected, and checks that `ClipMove()` refuses off-map movement instead of
sliding along an open axis. Because unrelated fixture tiles are removed, the
only possible obstruction is the coordinate bound under test. `GameStop()`
restores collision state through `ShutdownGameLevel()` and `InitObjects()`.

`TestSimulation()` additionally covers fixed-step input behaviour: one
`GameStep(0)` does not move, `GameStep(1)` consumes a key press, a later
`GameStep(2)` with no input does not move, cleared keys do not move the player,
opposing turn inputs cancel, and a long-pause step is bounded like the
normal path.

### Restart and reset

`TestRestart()` uses `RunRestartCycle()` twice. Each cycle:

1. Starts a synthetic game and captures a known initial snapshot: player
   `(2*TILEGLOBAL+32768, 2*TILEGLOBAL+32768)`, tile `(2,2)`, angle `0`,
   health `100`, ammo `8`, lives `3`, `TimeCount == 0`, one closed door.
2. Moves the player, then deliberately dirties actor reservation
   (`actorat[10][10]`), `staticblock`, a map tile, door action/position and
   pushwall state.
3. Calls `GameStop()`, asserts the map, actor, static and pushwall state are
   cleared, starts a fresh game, and compares the snapshot with the initial
   one.
4. Compares the result of two complete cycles.

The snapshot is an explicit scalar projection (positions, counters, flags and
boolean grid occupancy); no raw pointer, padding or uninitialised byte is
hashed.

### Deterministic replay and fixed seed

`TestDeterministicReplay()` starts `GameStartMap(0, 0, 2, 42)` twice, each
time after a full `GameStop()` and `IN_ClearKeysDown()`. Both sessions replay
the same 61-tick logical input script through the shared `ReplayInputs()`:

- hold `UpArrow` for 40 ticks to approach the closed door;
- release, then `Key(sc_Space)` to use the door;
- hold `UpArrow` for 10 ticks while the door opens;
- turn with `RightArrow`, then move again, and finish with an idle tick.

Key-down/key-up events are balanced. `CaptureReplayState()` records player
position/tile/angle, `TimeCount`, health/ammo/lives/keys/score, episode/map/
difficulty/weapon, `playstate`, actor and door counts, door coordinates/lock/
orientation/action/position/tic-count/runtime tile, actor-grid occupancy at
the door, pushwall state, and player link/state null flags.
`CheckReplayStatesEqual()` compares these fields individually.

### Presentation-rate determinism

`TestPresentationRateDeterminism()` reuses the same seed, input script and
snapshot comparison. The only difference is presentation activity:

- Session A: `WL_PresentCapture(t)` plus `WL_PresentSample(WL_TickNS(t), ...)`
  after every one of the 61 ticks (61 captures).
- Session B: the same calls every fourth tick (15 captures).

The capture counts are asserted, so the two schedules cannot silently become
identical. Presentation uses the existing read-only snapshot path;
`WL_PresentCapture()` copies authoritative state and `WL_PresentSample()`
writes only caller-owned storage. No extra Classic render call was added to
fake a different presentation rate. Both sessions end with identical
authoritative state after 61 simulation ticks.

### Classic renderer side-effect characterisation

`TestClassicRenderSideEffects()` calls the exact Classic rendering function
`ThreeDRefresh()` directly, not `WL_PresentSample()`. The deterministic setup
places the player at the west edge of tile `(3,2)`, spawns a visible actor at
`(4,2)`, a hidden actor at `(10,10)`, and places a `bo_clip` bonus at `(3,2)`.
`spotvis` is cleared and actor visibility flags are seeded so the before state
is known.

After `ThreeDRefresh()` the test asserts:

- `spotvis[3][2]` and `spotvis[4][2]` are marked by ray traversal, while
  `spotvis[10][10]` behind the closed door is not;
- the visible actor gains `FL_VISABLE` and becomes active;
- the hidden actor's stale `FL_VISABLE` flag is cleared;
- `DrawScaleds()` called `GetBonus()`: ammo changes from `8` to `16` and the
  static's `shapenum` becomes `-1`.

This is a characterisation of current behaviour. It would fail if any of
those side effects disappeared. It uses no timing waits, SDL window or owned
WL6 data.

  Wolfenstein data or external installations.

  was exercised in this revision.
- The presentation-rate test varies snapshot capture frequency over identical
  70 Hz simulation ticks; it is not a full Classic renderer-at-different-refresh

  presentation suite included in the user-supplied full regression.

  existing 60-240 FPS presentation suite; the agent personally ran only the
  focused synthetic command.
