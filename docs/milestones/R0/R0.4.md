## Purpose and scope

R0.4 adds a deterministic, synthetic visual regression baseline for the
existing Classic 4:3 and Enhanced widescreen renderers. It uses the established
`tests/render_tests.c` executable, Python unittest driver and synthetic archive
generator. No production source, renderer architecture, gameplay timing, save
format, dependency, commercial asset or `3rdparty/` content changed.

The baseline protects canonical indexed pixels. Existing SDL dummy/software
tests continue to protect palette conversion, logical presentation, black bars,
resize/fullscreen transitions and exact output where that backend is stable.
Accelerated, physical-fullscreen and high-DPI output are not treated as
pixel-identical to the canonical baseline.

## Implemented functionality

- `tests/render_tests.c` freezes one shared synthetic world and emits a bounded
  `w3r-indexed-v1` format: 16-byte magic/version/width/height header followed by
  exactly one palette index per pixel.
- The shared scene fixes seed `0`, tick `0`, camera tile `(2,3)` plus half-tile
  offsets, angle `0`, view size `15`, pistol state, map geometry and palette.
  It contains corridor walls, a door, near/far statics, an actor, HUD and weapon.
- Classic captures retain the authoritative 320x200 framebuffer. Output
  captures apply deterministic nearest-neighbour 320x200-to-corrected-4:3
  presentation with centered black letterboxing.
- Enhanced captures use the existing `WL_RenderFrameAspect` and caller-owned
  indexed targets; no new rendering path was introduced.
- `tests/visual_baseline.py` validates format and dimensions, computes SHA-256,
  compares all metadata, performs exact pixel comparisons, reports changed-pixel
  counts and inclusive difference bounding boxes, and writes palette-correct
  8-bit BMPs with only Python's standard library.
- `tests/fixtures/visual_baselines.json` locks metadata and hashes.
  `tests/fixtures/visual_baselines.zip` deterministically stores the 32 exact
  synthetic indexed baselines (18,976,516 bytes uncompressed; about 1.2 MB
  committed) so a regression can produce spatial diagnostics rather than only
  a hash failure.
- `tests/test_render.py` generates and validates the baseline on every synthetic
  render run. It also proves exact equality, deliberate one-pixel failure,
  dimension failure and metadata failure. The synthetic gate cannot skip when
  owned Wolfenstein data is absent.
- Generated captures, BMPs, manifests and logs remain under ignored
  `build/validation/R0.4/`.

Classic rendering still calls the existing paused gameplay renderer. No
`spotvis`, `FL_VISABLE`, `GetBonus()` or other observable Classic behavior was
moved or removed; the R0.3 characterization remains intact. Simulation remains
70 Hz.

## Manifest contract

The JSON root contains `schema_version` and a sorted `captures` array. Each
capture records:

- stable capture ID and scene ID;
- rendering mode and named state;
- synthetic fixture SHA-256 identity and semantic source revision;
- authoritative tick, fixed seed, camera, view, weapon and relevant door or
  pushwall state;
- internal and output dimensions plus selected aspect;
- palette identity, indexed format and SHA-256 pixel hash;
- capture method, SDL/backend applicability and comparison policy.

`source_revision` is the versioned baseline contract
`R0.4-baseline-v1`, not a self-referential Git commit. The report records the
Git base and the final handoff supplies the commit containing the baseline.
Fixture and palette hashes bind the pixels to their actual generated inputs.

## Comparison rules

1. Canonical Classic and Enhanced indexed captures are exact. There is no
   tolerance and no ignored region.
2. Header schema, dimensions, payload length, capture ID set and all metadata
   must match before pixels are accepted.
3. SHA-256 is the fast unchanged check. On a hash mismatch, the comparator
   loads the locked pixels, counts every changed pixel and reports the inclusive
   `(min_x, min_y, max_x, max_y)` box plus both hashes.
4. Classic corrected output is deterministic nearest-neighbour indexed scaling
   using the original six-bit palette identity. BMP review expansion uses
   `(value << 2) | (value >> 4)`.
5. Existing dummy/software SDL exact comparisons remain exact. No arbitrary
   tolerance is applied to accelerated, physical-fullscreen or high-DPI output;
   those configurations require separate platform evidence and visual review.
6. An intentional baseline update requires `WOLF3D_UPDATE_BASELINES=1`, review
   of both manifest/archive changes and retained BMPs, followed by an ordinary
   validation run. The update flag is never part of the canonical command.

## Validation interface

Canonical synthetic graphics command:

```sh
python3 -m unittest discover -s tests -p test_render.py -v
```

Review-capture command:

```sh
WOLF3D_BASELINE_DIR="$PWD/build/validation/R0.4/captures" \
  python3 -m unittest discover -s tests -p test_render.py -v
```

The canonical command reports unittest progress, build failures, owned-data
skips and comparison diagnostics, and exits nonzero on a required synthetic
regression. Callers should apply an external timeout until R0.6 supplies the
common bounded runner. The retained-capture command produced 32 `.w3i`, 32 BMP
and one run manifest in this validation.

## Manual inspection checklist

Run the retained-capture command, record reviewer/date/OS/GPU/SDL driver, and
inspect every named state. At minimum confirm:

- Classic 640x480 is corrected 4:3; 1280x720 has equal black side bars;
  1001x601 is centered and not stretched or cropped.
- Enhanced 4:3 agrees vertically with Classic while 16:9, 16:10, 21:9 and 32:9
  reveal additional horizontal geometry without stretching.
- corridor walls/door, near and far statics and actor have plausible depth and
  occlusion; HUD and weapon remain centered and unclipped;
- door closed/half/open and pushwall initial/moving/boundary states progress in
  the expected direction without gaps or overdraw;
- edge sprites/walls clip at the viewport and never overwrite the bevel/HUD;
- Auto 1001x601 uses the expected wide canvas; initial and restored images are
  visually identical;
- on any available accelerated, high-DPI or physical-fullscreen target, record
  PASS/FAIL/NOT RUN separately rather than comparing it to software pixels with
  an invented tolerance.

## Limitations and remaining risks

- Human visual approval is NOT RUN, so A12 and milestone closure remain open.
- No owned Wolfenstein data was available; 21 existing compatibility or
  installation tests skipped exactly as before. Synthetic baseline coverage is
  independent of those assets.
- Only Linux x86-64 with SDL dummy/software was executed. Windows, macOS,
  accelerated renderers, real fullscreen, high-DPI and multiple GPUs are NOT
  RUN for this revision.
- Canonical Classic output scaling is a small test-side indexed oracle. Actual
  SDL palette upload, logical rectangle and full-output geometry are separately
  covered by the existing video/display tests, not by assuming every backend's
  final pixels are identical.
- The semantic source revision avoids an impossible manifest hash depending on
  the commit that contains itself. Git provenance is carried by the containing
  commit and this report.
